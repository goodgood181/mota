# 《轮回之塔》— C++ 魔塔 试玩版

> **你救不了她。但你可以试一千次。**

把「死亡读档」本身写成剧情：存档可以丢，轮回不会。每一次死亡都会
重开 1F——但怪物图鉴、已探索地图、记忆碎片与执念会穿过轮回保留，
这正是设计文档《轮回之塔》的 M1+M2+核心 M4 切片。

---

## 图形界面

默认以 **Win32 图形窗口** 运行（GDI 双缓冲）：

- 每个 NPC / 怪物 / 道具 / 主角都有 16×16 **像素画插图**（来源 `src/sprites.h`，
  调色板索引逐行定义），地图格 2 倍整数放大为 32px
- 地图、面板、日志、对话、商店、图鉴、战斗预览全部落在图形窗口内，
  中文用系统雅黑渲染
- 全部像素画汇总图：`build\sprites_sheet.png`（由 `bld\sprite_export.exe` 生成）
- 命令行开关：`--console` 回退纯终端模式；`--shot out.bmp` 无窗口截一帧游戏画面；
  `--script xx.txt` 隐藏窗口按脚本按键（自检用）

## 楼层设计：门是必经之路

每一扇门都横切在**唯一通道**上，不可能绕过去：

- **1F**：黄钥匙在出生后的必经走廊 → 黄门横切走廊 → 楼梯在门后
- **2F**：商店与蓝钥匙都在必经走廊 → 蓝门卡住唯一竖道 → 出口在门后
- **3F**：无门，红钥匙在此层必经路上拾取，供 4F 使用
- **4F**：红门卡住唯一竖道，门后是石魔（领域）+ 吸血鬼的走廊
- **5F**：守门人·赤铠堵在最终楼梯正前方（`Q` 在 `>` 左侧），回避不了

自检把这条规则**数学化**验证（不再是目测）：每扇门把图删掉后，门前与门后分属
不同连通分量；所有钥匙都在开门前的必经路径上；开门后全层连通无孤岛。

## 冒烟与自检

```bat
build.bat --selftest        :: 60 项自动检查（数据/门必经·钥匙前置·开锁链/战斗/成长模拟/条件/结局/存档兼容/实战）
powershell -File tools\gen_maps.ps1   :: 校验全部 20 层地图行宽（只校验不写入）
build\mota.exe --shot build\frame.bmp   :: 无窗口渲染一帧游戏画面并导出（像素级自动校验精灵渲染）
build\mota.exe --script scripts\smoke1.txt   :: 隐藏窗口跑完整 GUI 流程（战斗/商店/死亡/轮回/存档）
build\mota.exe --script scripts\smoke2.txt   :: 隐藏窗口验证读档
build\mota.exe --script scripts\tA_preview.txt   :: 回归：战斗预览中按方向键不再出现空白帧
build\mota.exe --script scripts\tE_pause.txt     :: 回归：暂停菜单中按方向键不再出现空白帧
```

> 空白帧机制说明：`ui::present()` 上屏后会清空本帧缓冲，因此"进入循环后只画一次、循环体内直接 `readKey()`"的交互层（战斗预览/暂停菜单/遗物选择/经验突破）在按无效键（方向键/WASD）重入循环时会再上屏一帧纯背景——表现为整窗变黑、按任意有效键后恢复。现已在循环头重画修复；`MOTA_BLANK=1` 环境变量可复现/回归该缺陷。

## 构建

- **Windows / MSVC**：`build.bat`（需要 `cl` 在 PATH 中，如 VS 开发者命令行），产物 `build\mota.exe`
- **CMake**：`cmake -S . -B build-cmake && cmake --build build-cmake`（构建后自动把 `data/` 复制到可执行文件旁边；`ui.cpp` 仅在 Windows 编译）

数据目录解析顺序：可执行文件旁 `data\` → 当前目录 `data\` → 上一级 `data\`。

## 数值速览（试玩版）

- 玩家初始 300 血 / 20 攻 / 10 防
- 1F：绿史莱姆×2（3 金）、金币袋×2，黄钥匙教学，暗墙（`H`）藏血瓶
- 2F：商人（攻/防 25 金起售且逐次 ×2 涨价，血瓶 10 金起）；蝙蝠（连击）/ 骷髅（前期必死）
- 3F：红钥匙、分裂史莱姆、诅咒幽灵、碎片「回忆之一」
- 4F：吸血鬼（吸血）、石魔（领域，紧挨骷髅演示光环）、碎片「回忆之二」
- 5F：守门人·赤铠（2000 血 / 200 攻 / 80 防 / 先攻）——**试玩版必死**，这是轮回的第一课
- 碎片×3 → 真结局达成度；轮回 ≥10 后怪物挨打会求饶让路、第零层开启、碎片/结局彩蛋门槛

> 平衡偏差说明：设计稿中绿史莱姆掉落 1 金，切片内调整为 3 金，配合 1F 两个
> 金币袋，保证首轮回即可在 2F 商人处完成一次购买，避免死档式刷怪。

## 数据格式（data/）

```
data/
├── monsters.json   怪物（数值/技能/图鉴文案）
├── items.json      道具与遗物（键/血/攻/防/金/碎片/遗物效果）
├── floors.json     楼层表（每层怪物、道具、NPC、事件、出生点，引用 floors/*.txt）
├── floors/         13×9 文本地图（# 墙 · 地 / < > 楼梯 / 1-3 门 / H 暗墙 / T 机关 / @ 出生点 / s 商店 / n NPC）
├── events.json     对话场景（when 条件、choices 分支、cinema 电影式、once 一次性）
└── endings.json    结局（条件数组，按优先级排列，B 真结局在 A 坏结局之前）
```

事件条件语法示例：`loop>=10`、`frag>=7`、`flag_zero_deal`、`seen_enter_floor_2`、
`killed(any)`、`!killed(bat_small)`，支持 `&&` / `||`；正文支持 `{loop}` `{frag}` 占位符。
